# Bounded interview method

Use this method for material uncertainty, not as a mandatory checkpoint for every task.

1. Read the current request, approved plan, applicable project instructions and relevant implementation. Separate established facts, settled decisions, consequential choices and future questions. Investigate discoverable facts using permitted read-only tools before asking the user; research permission does not authorize live household access. Only an already-authorized orchestrator may delegate investigation, using the existing explorer role.
2. Map which choices depend on other choices. Ask at most **three independent questions per round**, choosing those whose prerequisites are known and whose answers materially change the current task. Use the client's question tool when available and suitable, otherwise ask in conversation. Offer meaningful alternatives and a recommendation with its tradeoff. Do not ask dependent questions until their prerequisites are answered.
3. Incorporate answers and recompute what remains. Do not reopen settled decisions without contradictory evidence or a user-requested change. Resolve routine implementation details through existing conventions; do not add approval steps for them. Never treat silence as approval of a required decision.
4. Explicitly defer later-milestone questions with a reason and revisit condition. Label nonblocking assumptions. Stop when the current task has observable acceptance criteria, explicit non-goals, and no unresolved decision that prevents implementation. If the user stops earlier, summarize unresolved questions honestly instead of asserting readiness.

The output is a decision summary, not implementation authorization. An enclosing workflow continues only as allowed by the original request; a planning-only request stops at the summary/specification. Preserve references to the approved plan instead of producing a competing master specification.
